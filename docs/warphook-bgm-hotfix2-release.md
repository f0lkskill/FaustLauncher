# WarpHook 0.9.52 / BattleBGMExtend 2.0.7

本次将已经离线验证的 hotfix2 移植补丁应用到本地 addons，移除版本号中的测试后缀。没有改动用户的 rules.json 和插件设置。

## 修复范围

- Battle_Cp9_Boss_10 在临时事件预检、实际事件创建后、上一首恢复时设置 Ryoshu=1；其他曲目不改参数。
- 预检失败保留原曲。实际切换失败先清理，再尝试同一进程会话中成功提交的上一首或默认列表；清理失败不继续叠播，恢复失败不误报成功。
- 自动切换失败清除去重状态，允许下回合重试；手动恢复失败保留规则快照。
- CMD10 携带五个已解析的 IL2CPP 元数据导出名，验证字段静态性、值类型大小、方法参数 byref、bool 返回和实例标记；共享协议仍为 v14，布局不变。
- 保留移植版按条件失效解锁/优先级降级的语义，不引入上游永久优先级锁。

## 验证

候选版本已完成 Python 回归 18 项、直接 include 实现的原生 stub harness 85 项断言、协议布局检查及构建。候选包 50 个文件哈希逐项校验通过。

正式目录的 DLL 与已构建候选一致：SHA256 `b4424c692cff5e86e1f35c3566661a2d9f43b6eb64e9839670dfccacf017b3c8`。

离线 stub 不证明真实 FMOD/IL2CPP ABI、游戏生命周期或音频输出。本轮没有扫描、注入或听音验证；`verified=False` 保持真实含义。旧 worker 的 GC 显式注册风险仍存在，本次不宣称修复。上游 hotfix1 的被动入口捕获和 FixedUpdate/回合末等待时序没有全部移植。

## 更新要求

WarpHook DLL、Python 文件与 BattleBGMExtend 必须配套更新；重启启动器及游戏后加载新版。不要同时启用上游独立版与移植版。保留自定义规则与设置。同步前原文件备份在 cache/warphook-backups/release_0952_20261106_002848。
