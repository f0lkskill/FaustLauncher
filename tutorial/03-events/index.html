    03 事情发生的时候通知我¶

    上一篇是「我主动让游戏做事」。这一篇反过来：游戏里发生事的时候，让我知道。

    新手最容易想到的写法是「一直循环，发现变化就处理」。但读游戏内存是跨进程往返， 一次 20–40 毫秒，一秒看一眼全场就要几百毫秒——卡。所以正确的写法是让游戏通知你。

    在 warp.game 里，这件事被压成了一个函数：

    game.on_round_start(_on_round)

    你只写 _on_round 这个函数，什么时候调它是框架的事。

    示例：战况播报¶

    # -*- coding: utf-8 -*-
"""战况播报：每回合开始时把场上所有单位的血量打到日志里。

这一篇的重点不是「怎么钩方法」，而是：**你只写一个函数，什么时候调它由框架负责。**

    game.on_round_start(_on_round)

``_on_round`` 收到的是一个 ``Battle`` —— 那一刻场上所有单位的快照。
"""

from typing import cast

if False:  # 仅供类型检查器阅读
    from warphook.base import WarpNamespace

ADDON_ARG = globals().get('ADDON_ARG') or {}
ADDON_NAME = ADDON_ARG.get('AddonName')
ADDON_MANAGER = ADDON_ARG.get('AddonManager')
_NS = ADDON_ARG.get('Namespaces')
_W = cast("WarpNamespace", _NS.space('warp') if _NS is not None else None)
game = _W.game


def _log(message):
    print(f'[{ADDON_NAME}] {message}', flush=True)


def _settings():
    try:
        info = (ADDON_MANAGER.get_addon_info(ADDON_NAME)
                if ADDON_MANAGER is not None else None) or {}
    except Exception:  # noqa: BLE001
        info = {}
    return info.get('settings') or {}


def _on_round(battle):
    """每回合开始被调一次。``battle`` 是那一刻的全场快照。"""
    _log(f'—— {battle.scene_name}：场上 {battle.count} 个单位 ——')
    if not _settings().get('播报血量', True):
        return
    for u in battle.units:
        tags = []
        if u.is_panic:
            tags.append('混乱')
        if u.is_break:
            tags.append('崩溃')
        if not u.alive:
            tags.append('已阵亡')
        tail = ('  ' + '/'.join(tags)) if tags else ''
        _log(f'  #{u.id:<2} 人格 {u.identity:<6} '
             f'HP {u.hp}/{u.max_hp}  SP {u.sp}{tail}')


def _now():
    """菜单用：不等回合，现在就看一眼。"""
    units = game.units()
    _log(f'现在场上有 {len(units)} 个单位')
    for u in units:
        _log(f'  #{u.id:<2} 人格 {u.identity:<6} HP {u.hp}/{u.max_hp}')


game.on_round_start(_on_round)
game.on_scene_changed(
    lambda scene: _log(f'场景切换 → {scene["name"]}'))
game.start(menu=(
    ('立刻看一次', _now),
    ('看连接状态', lambda: _log(game.describe())),
))


def on_unload():
    game.close()

    {
    "name": "战况播报",
    "desc": "每回合开始时把场上所有单位的血量和状态打到日志里。演示「游戏里发生事的时候通知我」这种写法：插件只写一个回调函数。",
    "requires": [
        "WarpHook"
    ],
    "settings": {
        "enable": true,
        "播报血量": true
    },
    "version": "0.1.0"
}

    进战斗、打一个回合，日志里就会出现：

    [战况播报] —— 战斗：场上 11 个单位 ——
[战况播报]   #1  人格 10115  HP 245/248  SP 45
[战况播报]   #2  人格 8732   HP 60/526
[战况播报]   #3  人格 0      HP 62/62
...

    通知是怎么到你手里的¶

    sequenceDiagram
    participant Game as 游戏
    participant DLL as warp_host.dll
    participant Py as warp.game 心跳线程
    participant CB as 你的回调

    Game->>DLL: 回合开始（OnRoundStart_Model 被调用）
    DLL->>DLL: 命中计数 +1，把管理器存进对象槽 28
    loop 每 0.25 秒
        Py->>DLL: 读命中计数
    end
    Py->>Py: 发现计数涨了 → 抓管理器、组一个 Battle
    Py->>CB: 调 _on_round(battle)
    CB->>CB: 你的代码（在心跳线程上跑）

    所以：通知最多有 0.25 秒延迟，而你的回调慢一点也不会卡游戏。

    Battle 是什么¶

    回调拿到的参数是那一刻的全场快照：

    属性 说明
    battle.units 单位列表（Unit 对象）
    battle.count 单位数
    battle.alive 还活着的单位（列表推导好了）
    battle.scene / battle.scene_name 场景编号 / 中文名
    battle.by_id(1) 按界面上那个编号找
    battle.by_identity(10115) 按人格 ID 找

    注意它是快照：拿到 Battle 的时候单位列表不会变，但单位里的数值每次读都是现读的。 想留一份历史就自己抄一份。

    三种现成的通知¶

    每回合开始¶

    game.on_round_start(lambda battle: print(battle.count))

    绑的是游戏自己的「回合开始」。一回合一次，频率很低，随便你在这里干什么 （读全场、弹窗、写文件都行）。

    场景切换¶

    game.on_scene_changed(lambda scene: print(scene['name']))

    scene 是个字典：{'value': 1, 'name': '战斗', 'time_scale': 1.0, 'entries': 1}。 场景编号对照：

    值 场景 值 场景
    0 登录 5 镜像地牢
    1 战斗 6 铁路
    2 主界面 7 剧情镜像
    3 剧情 8 ProjectGS
    4 地牢 9 Rpg

    进战斗 / 出战斗¶

    game.on_battle_start(lambda battle: print('开打了', battle.count))
game.on_battle_end(lambda scene: print('打完了', scene['name']))

    这两个是上面那个的语法糖，专门给「只在战斗里干活」的插件用。

    回调跑在哪个线程¶

    独立的后台线程，不是游戏的线程。所以：

    • ✅ time.sleep() 是安全的
    • ✅ 弹窗、读文件、发网络请求都不影响游戏
    • ⚠️ 回调 慢 会堆积：一次读全场是几十次往返，可能要 1 秒
    def _on_round(battle):
    for u in battle.units:   # 11 个单位
        print(u.hp)          # 每次 20–40ms，一圈下来约 0.3 秒

    0.3 秒对回合级回调完全没问题。但如果你在 on_scene_changed 里也这么干， 切场景时会明显卡一下——按需读才是对的：

    def _on_scene(scene):
    if scene['value'] != 1:      # 不是战斗就什么都不做
        return
    ...

    为什么没有 on_hp_changed¶

    你可能会想「血量变了就通知我」。这个能力故意没做，原因是成本：

    • 血量变化发生在每一次受击，一回合几十次；
    • 而每次通知都要跨进程往返，真做出来就等于每帧都在读内存，反而卡。

    正确的做法是在回合边界比较：

    _last = {}

def _on_round(battle):
    for u in battle.units:
        old = _last.get(u.id)
        if old is not None and u.hp < old:
            print(f'#{u.id} 掉了 {old - u.hp} 点血')
        _last[u.id] = u.hp

    需要「掉血的那一帧」再动手的插件，看第 08 篇——那里讲怎么钩住具体的游戏方法。

    这一篇你该记住的¶

    • 通知 = 你写函数，框架决定何时调
    • on_round_start / on_scene_changed / on_battle_start / on_battle_end
    • 回调参数是快照（Battle / scene 字典），单位里的数值是现读的
    • 回调在后台线程，sleep 安全，但别在回调里无脑遍历全场
    • 想要「变化的那一瞬间」，得自己比较，或者用第 08 篇的钩子
