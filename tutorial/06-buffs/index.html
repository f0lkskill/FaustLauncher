    06 解析 buff¶

    buff 是这套接口里封装得最多的一块——因为它要读文字，比读数字麻烦得多。 你只需要记住三个入口：

    u.buff_count()          # 有几个
u.buffs                 # 全部，列表
u.buff("Breath")        # 找一个（英文 ID / 中文名 / 序号都行）
u.has_buff("呼吸法")     # 有没有

    Buff 能读什么¶

    属性 含义 例子
    b.name 中文名（游戏里显示的那个） 呼吸法
    b.key 英文 ID（数据里真正的标识） Breath
    b.stack 当前层数 / 强度（界面上那个大字） 85
    b.turn 剩余次数 / 回合 28
    b.max_stack 层数上限 99
    b.max_turn 次数上限 99
    b.stack_ratio 层数比例 0..1 0.858
    b.icon 图标 ID Buff_Breath
    b.raw() 九个字段的字典 — 
    for b in u.buffs:
    print(b.key, b.stack, b.turn)

    buff 在哪¶

    buff 挂在单位的 _buffDetail 上，是一个链表结构：

    flowchart LR
    UM["BattleUnitModel"] -->|"+0xE0"| BD["BuffDetail"]
    BD -->|"+0x10 解引用"| L["List&lt;BuffModel&gt;"]
    L -->|"第 i 个"| BM["BuffModel"]
    BM -->|"+0x58"| BI["BuffInfo<br/><i>层数 stack / 次数 turn</i>"]
    BM -->|"+0x68"| SD["BuffStaticData<br/><i>英文 ID / 图标 / 上限</i>"]
    • 层数与次数（b.stack b.turn）在 BuffInfo 里，走 DLL 代读；
    • 英文 ID 与图标（b.key b.icon）在 BuffStaticData 里，是字符串，要另外读；
    • 中文名（b.name）在 BuffInfo._name 里，也是字符串。

    key 和 name 的区别（重要）¶

    同一个 buff 有两个名字：

    • name 是中文显示名（呼吸法），跟着游戏语言走。玩家切成英文，它就变成别的。
    • key 是英文 ID（Breath），是数据里的真实标识，任何语言都一样。

    所以：给玩家看用 name，写逻辑一律用 key。

    if u.has_buff("Breath"):        # ✅ 换语言也不会坏
    ...

if u.has_buff("呼吸法"):         # ⚠️ 游戏换语言就失效
    ...

    一只手数完的实例¶

    我方人格 10115（浮士德·魁首）身上的 9 个 buff，实测值：

    中文名 key 层数/上限 次数/上限
    呼吸法 Breath 85 / 99 28 / 99
    指令加护 BlessingOfIndexPrescriptAlly 9 / 9 0 / —
    代行[赫尔墨斯] StackYisangSpecialSkill 9 / 9 0 / —
    烧伤 Combustion 3 / 99 1 / 99
    守护 Protection 1 / 10 0 / —
    遮盖伤口的假面 BurningWoundYisangMask 1 / 1 0 / —

    key 是从游戏的数据表里直接读出来的字符串，所以它们看起来像英文变量名——那就是原样。

    示例¶

    {
    "name": "buff 观察",
    "desc": "读取单位身上的 buff 名字、层数、剩余次数",
    "authors": ["你的名字"],
    "requires": ["WarpHook"],
    "settings": {
        "enable": true
    },
    "version": "0.1.0"
}

    # -*- coding: utf-8 -*-
"""06 篇示例：读 buff。"""

from typing import cast

ADDON_ARG = globals().get('ADDON_ARG') or {}
ADDON_NAME = ADDON_ARG.get('AddonName') or 'buff 观察'

_NS = ADDON_ARG.get('Namespaces')
_W = cast("WarpNamespace", _NS.space('warp') if _NS is not None else None)
game = _W.game


def _log(message):
    print(f'[{ADDON_NAME}] {message}', flush=True)


def _list_buffs():
    u = game.player()
    if u is None:
        _log('现在不在战斗里')
        return
    _log(f'编号 {u.id}（人格 {u.identity}）身上 {u.buff_count()} 个 buff：')
    for b in u.buffs:
        _log(f'  {b.name or b.key}  {b.stack}/{b.max_stack} 层  '
             f'{b.turn}/{b.max_turn} 次   [{b.key}]')


def _check():
    """判断身上有没有某个 buff —— 插件最常用的写法。"""
    u = game.player()
    if u is None:
        return
    if u.has_buff('Breath'):
        b = u.buff('Breath')
        _log(f'身上有呼吸法：{b.stack} 层，还剩 {b.turn} 次')
    else:
        _log('没有呼吸法')

    if u.is_break:
        _log('注意：已混乱')
    if u.hp_ratio is not None and u.hp_ratio < 0.3:
        _log('注意：血量低于 30%')


def _on_round(battle):
    """回合边界把全场的 buff 数报一遍。"""
    for u in battle.units:
        names = [b.key for b in u.buffs]
        if names:
            _log(f'#{u.id}（{u.identity}）{len(names)} 个：{", ".join(names)}')


game.start(menu=(
    ('列出我方 buff', _list_buffs),
    ('检查几个 buff', _check),
))
game.on_round_start(_on_round)

    点「列出我方 buff」：

    [buff 观察] 编号 1（人格 10115）身上 9 个 buff：
[buff 观察]   遮盖伤口的假面  1/1 层  0/0 次   [BurningWoundYisangMask]
[buff 观察]   呼吸法  85/99 层  28/99 次   [Breath]
[buff 观察]   烧伤  3/99 层  1/99 次   [Combustion]
...

    文字是怎么读出来的¶

    数字走的是「DLL 代读」，一次往返 20–40ms。但文字不行——那条通道只能回一个 32 位的数。所以 b.name / b.key 走的是另一条路：WarpHook 拿到字符串对象的地 址，再由插件进程直接从游戏内存里读出来（只读，安全）。

    这条路的代价是要先找到游戏进程（第一次调用会慢一点），之后每次读一个 buff 名 大约几十毫秒。所以：

    • u.buff_count() 很快（一次往返）
    • u.buffs 里的 b.stack / b.turn 也快（每项往返一次）
    • b.name / b.key 慢一点（每个字符串单独读）

    想在回合回调里报「全场每人的 buff 名单」，11 个单位 × 几个 buff × 每个字符串， 一秒以上是正常的。只在需要时读名字，或者只读你关心的那几个。

    只要「变了没变」的快速写法¶

    如果目的只是「这个 buff 出现了 / 消失了」，不需要文字：

    u.buff_ids()      # 每个 buff 的英文 ID 指纹（数字），比读字符串快

    它是 BuffStaticData.id 的哈希，同一个 buff 永远同一个数，换个 buff 就变。 想放到事件里做 diff 就够用了。

    这一篇你该记住的¶

    • u.buff_count() / u.buffs / u.buff(key) / u.has_buff(key)
    • Buff 给：name key stack turn max_stack max_turn icon
    • 写逻辑用 key（英文 ID），给玩家看用 name（中文名）
    • 读名字比读数字慢，别在循环里无脑读全场
    • 只要判断有无/变化，用 u.buff_ids()（数字指纹）
