    03 提交钩子¶

    弹窗是「我们主动让游戏做事」。钩子是反过来：游戏做某件事的时候，让我们插一脚。

    这是 WarpHook 最有价值的能力，也是所有「修改游戏逻辑」类插件的起点。

    心跳模型¶

    游戏主线程                          你的插件（启动器进程）
    │                                      │
    │  调用 BattleUnitModel.OnCreateUnitModel()
    │  ──► warp_host.dll 的 thunk 抢在前面
    │            │
    │            ├─ 命中计数 +1      ←──── warphook 每 0.25 秒读一次这个数
    │            ├─ 把 self 存进对象槽 27
    │            ├─ （可选）拦下原方法
    │            └─ 放行 / 继续
    │
    │  回到正常流程

    注意这里没有「游戏调用 Python」这种事——Python 不在游戏的线程里。 游戏那边只做计数和最轻的记录，插件这边靠轮询发现「刚才命中了 N 次」。 这个模型决定了后面所有行为的边界，先记住它。

    一个钩子就是一个 dict¶

    {
    'klass': 'BattleUnitModel',     # 类名
    'method': 'OnCreateUnitModel',  # 方法名
    'argc': 0,                      # 参数个数（不含 self）
    'actions': 0,                   # 0 = 只看不碰
    'cache': (0, 27),               # 命中时把 self 存进对象槽 27
}

    常用字段全表：

    字段 默认 作用
    klass / method — 要钩的方法，必须跟 dump 里的名字一字不差
    argc 0 参数个数（不含 self）。数错了整个调用会错位
    actions 0 动作位。0 只看；flags 里的 HF_BLOCK 才是「拦」
    flags 0 HF_BLOCK(0x01) 拦下原方法 / HF_ONCE(0x02) 只触发一次 / HF_DEDUPE(0x04) 值没变就不投递
    cache — (参数序号, 槽号)：命中时把那个参数（0 是 self）的指针存进对象槽
    guard — (vars 槽号, 值)：那个槽等于这个值时才放行（当开关用）
    every 1 每 N 次命中才算一次
    chance 100 触发概率（百分比），调试随机效果用
    delay_ms 0 命中后延迟多久再执行动作
    when 0 1 = 在原方法调用之后才处理（构造函数要读的字段是之后才填好的）
    ret_kind / ret_slot — 把原方法的返回值取出来（'int32'/'float'）放进事件的某一格
    reads — 命中时直接读几个字段，见第 04 篇
    event — 每次命中都往事件队列塞一条现场记录，见第 07 篇

    完整示例：看住「单位被创建」¶

    # -*- coding: utf-8 -*-
"""单位观察：钩住「单位被创建」这一瞬间。

钩子是 WarpHook 的第一类原语：**游戏调到某个方法时，让你插一脚**。
这一篇只做最轻的一种——不拦、不改，只在旁边看着并记录。

选的靶子是 ``BattleUnitModel.OnCreateUnitModel``：每进一次战斗，
游戏会给场上每个单位各调一次。频率低、不会被内联、而且 ``self`` 就是这个单位本身，
非常适合第一次练习。
"""

import time
from typing import cast

if False:  # 仅供类型检查器阅读
    from warphook.base import WarpNamespace

ADDON_ARG = globals().get('ADDON_ARG') or {}
ADDON_NAME = ADDON_ARG.get('AddonName')
ADDON_MANAGER = ADDON_ARG.get('AddonManager')
_NS = ADDON_ARG.get('Namespaces')
_W = cast("WarpNamespace", _NS.space('warp') if _NS is not None else None)

# 我们自己要用的对象槽。0..23 是成就插件的主段，24..31 是辅助段，
# 插件应该从 27 起往高用，避免跟别人撞车。
SLOT_UNIT = 27

# BattleUnitModel 里两个字段的偏移（第 05 篇会讲这些数从哪来）
OFF_INSTANCE_ID = 0x60

_count = 0


def _log(message):
    print(f'[{ADDON_NAME}] {message}', flush=True)


def _settings():
    try:
        info = (ADDON_MANAGER.get_addon_info(ADDON_NAME)
                if ADDON_MANAGER is not None else None) or {}
    except Exception:  # noqa: BLE001
        info = {}
    st = info.get('settings') or {}
    return bool(st.get('报编号', True))


def _hook_spec():
    """钩子的声明。一个钩子就是一条 dict，字段跟 Host.hook() 的参数一一对应。"""
    return [
        {
            'klass': 'BattleUnitModel',
            'method': 'OnCreateUnitModel',
            'argc': 0,          # 这个方法除了 self 没有参数
            'actions': 0,       # 0 = 什么都不做，只是让我们知道它被调了
            'cache': (0, SLOT_UNIT),   # 命中时把 self 的指针存进对象槽 27
        },
    ]


def _push():
    host = service.host()
    host.configure(hooks=_hook_spec(), texts=[])
    return host.push(True) not in ('共享内存不可用',)


def _on_create_unit(host):
    """每次有单位被创建时被调一次（跑在 Service 的派发循环里）。"""
    global _count
    _count += 1

    ptr = host.object_ptr(SLOT_UNIT)
    if not ptr:
        _log(f'第 {_count} 个单位：槽 {SLOT_UNIT} 是空的（指针没存进来）')
        return

    if not _settings():
        return

    # 从对象槽出发读一个 int 字段：偏移 0x60，读到就停（deref=False 表示
    # 「这个字段本身就是值」，而不是指向别的对象）。
    instance_id = host.read(SLOT_UNIT, [{'off': OFF_INSTANCE_ID, 'deref': False}],
                            kind='int', default=None)
    _log(f'第 {_count} 个单位：指针 0x{ptr:X}，编号 {instance_id}')


service = _W.plugin.Service(
    addon_name=ADDON_NAME,
    name=ADDON_NAME,
    sync=_push,
    auto=lambda: True,
    menu=(
        ('立刻重新挂一次', lambda: service.sync()),
        ('看看宿主状态', lambda: _log(service.describe(service.status()))),
    ),
)
# 钩子命中时调 _on_create_unit —— method 要和上面 _hook_spec() 里的名字一致。
service.on_hit(_on_create_unit, method='OnCreateUnitModel')
service.start()


def on_unload():
    return service.stop()

    {
    "name": "单位观察",
    "desc": "钩住「单位被创建」这一个瞬间，每出现一个新单位就在日志里报一次它的编号。演示钩子的三种用法：只观察、拦下来、按条件放行。",
    "requires": [
        "WarpHook"
    ],
    "settings": {
        "enable": true,
        "报编号": true
    },
    "version": "0.1.0"
}

    跑起来后，每进一次战斗，日志里会刷出一串：

    [单位观察] 第 1 个单位：指针 0x1DA198BFD80，编号 1
[单位观察] 第 2 个单位：指针 0x1DA1990A1C0，编号 2
...

    三种典型用法¶

    只看：actions: 0¶

    游戏照常走，我们只是知道「它刚才调了这个方法」，并且顺手把 self 存了下来。 上面的示例就是这种。适合做统计、记录、触发后续逻辑。

    拦下：flags: HF_BLOCK¶

    原方法不会执行，游戏就像什么都没发生。

    {
    'klass': 'BattleActionModelManager', 'method': 'Init',
    'argc': 0, 'actions': 0,
    'flags': _W.plugin.HF_BLOCK,
}

    这能做出「禁止抽卡扣钱」「不触发某段剧情」这类效果。但要想清楚：拦掉一个方法， 它的调用方会以为成功了，后面可能拿到 null 或默认值。拦之前先确认调用方容错。

    按条件拦：guard¶

    想「只在某种情况下动手」，用 guard 接一个开关变量：

    'guard': (0, 1)     # vars[0] == 1 时才放行（不拦）

    配合 host.popup/host.set_enabled，就能做出托盘菜单里的开关效果。 具体怎么往 vars 里写值，见第 07 篇。

    对象槽：把游戏的对象「挂」在这里¶

    cache: (0, SLOT_UNIT) 的意思：命中时把 self 的指针抄进对象槽 27。 之后任何时候都能用这个槽出发读东西：

    ptr = host.object_ptr(27)                                    # 拿指针本身
value = host.read(27, [{'off': 0x60, 'deref': False}], 'int')  # 从它出发读一个字段

    槽一共 32 个，被分成几段：

    槽 用途
    0..23 成就插件的主段（别用，会和它互相覆盖）
    24..26 你自己随便用
    27..28 建议插件从 27 起用
    29 宿主每帧缓存的场景根对象（GlobalGameManager）
    30 / 31 宿主每帧回调的保留位

    选靶子的三条经验¶

    这三条都是踩出来的，能省你很多时间：

    ① 小 getter 钩不到

    CharacterState::get_Hp、BattleUnitModel::get_Position 这种一行返回的 getter，在 AOT 编译时经常被内联到调用方里——方法本身还在，但游戏永远不会 真的「调用」它，所以钩子永远不命中。选体积大、带循环、带参数的方法。

    ② 同一个方法只能挂一条钩子

    如果成就插件已经钩了 BattleUnitModel.RefreshSpeed，你再钩它就装不上， 日志里是：

    hook: target already hooked elsewhere (27)

    换一个方法，或者用第 05 篇的「静态调用」完全绕开钩子。

    ③ 别看错类

    BattleUnit 和 BattleUnitModel 是两个不同的东西：BattleUnit 是你点选的那个 「场上格子」，BattleUnitModel 才是它的数据本体。钩错类什么也拿不到。

    装上去试¶

    1. 把 单位观察/ 放进 addons/，重启启动器，进战斗；
    2. 日志里每回合开始会刷出单位编号；
    3. 想确认钩子真的挂上了，看 addons/WarpHook/warp_host.log，应该有：
    hook installed (27)

    括号里是你占的槽号。如果看到 hook: class not found (27)，说明类名写错了； hook: method not found (27) 是方法名写错了。

    到这一步你该知道的¶

    • 钩子 = 一条 dict，描述「哪个类的哪个方法、要不要拦、要不要顺手存东西」
    • 游戏那边只计数，插件这边轮询 —— 不要在回调里假设自己在游戏的线程上
    • 三个 flag：拦（HF_BLOCK）、只一次（HF_ONCE）、去重（HF_DEDUPE）
    • 选靶子：大方法、不与人撞车、类名别认错
