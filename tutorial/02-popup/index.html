    02 让游戏弹一句话¶

    上一节的插件只会自己说话。这一节让游戏说话。

    目标：游戏跑到标题画面时，弹出一个原版系统弹窗，内容是你在设置里写的那句话。

    先说清楚：为什么不能直接 import warphook 就弹¶

    你的 scr.py 跑在启动器进程里，游戏是另一个进程。两个进程的内存互相看不见， 你不能在启动器里直接调游戏的函数。

    WarpHook 的做法是往游戏进程里塞一个 DLL（warp_host.dll），再由这个 DLL 在游戏的线程里替你去调游戏的函数。启动器和这个 DLL 之间靠一块共享内存通信：

    ┌─────────────── 启动器进程 ───────────────┐      ┌──────── 游戏进程 ────────┐
│  你的 scr.py                              │      │                          │
│      ↓ 调 host.popup("你好")              │      │   warp_host.dll          │
│  warphook 库 ──写共享内存的命令格─────────┼─────→│   读命令格               │
│                                          │      │      ↓                   │
│                                          │      │   在游戏主线程调游戏弹窗 │
└──────────────────────────────────────────┘      └──────────────────────────┘

    所以「弹窗」这件事分成两半：注入（把 DLL 塞进去）和下命令（写共享内存）。 Service 就是替你把前半段全做完的那个类。

    Service 帮你挡掉的四件事¶

    你可能没想到的麻烦 Service 的处理
    游戏还没启动 等，直到 LimbusCompany.exe 出现
    游戏启动了但 il2cpp 还没初始化 再等，直到 GameAssembly.dll 加载完
    DLL 已经注入过了 检测心跳，跳过重复注入
    游戏重启了 托盘里点一下就会重新走一遍；卸载时自动收尾

    你只交两样东西：

    • sync：一个函数，把「你现在想启用哪些钩子、哪些设置」写进共享内存；
    • menu：托盘菜单里那几项，以及点了调什么函数。

    完整代码¶

    # -*- coding: utf-8 -*-
"""弹一句：让游戏自己弹一个原版系统弹窗。

这一篇比 hello 多出来的东西只有一件：**我们和游戏之间隔着一个进程**。
插件跑在启动器里，游戏是另一个进程，所以要让游戏做事，必须先把宿主的
``warp_host.dll`` 注入进去，然后通过共享内存给它下命令。

这些事全在 ``warp.plugin.Service`` 里，插件只需要交两样东西：
``sync``（怎么把设置写进去）和 ``menu``（托盘里点哪一项干什么）。
"""

import threading
import time
from typing import cast

if False:  # 只为让类型检查器知道 WarpNamespace 长什么样，运行时不会执行
    from warphook.base import WarpNamespace

ADDON_ARG = globals().get('ADDON_ARG') or {}
ADDON_NAME = ADDON_ARG.get('AddonName')
ADDON_MANAGER = ADDON_ARG.get('AddonManager')
_NS = ADDON_ARG.get('Namespaces')

# ADDON_ARG 里的 Namespaces 就是 WarpHook 暴露给插件的入口。
_W = cast("WarpNamespace", _NS.space('warp') if _NS is not None else None)


def _log(message):
    print(f'[{ADDON_NAME}] {message}', flush=True)


def _settings():
    """返回 (弹窗内容, 是否自动弹一次)，每次都现读，用户改了立刻生效。"""
    try:
        info = (ADDON_MANAGER.get_addon_info(ADDON_NAME)
                if ADDON_MANAGER is not None else None) or {}
    except Exception:  # noqa: BLE001
        info = {}
    st = info.get('settings') or {}
    return (str(st.get('弹窗内容') or '来自插件的问候'),
            bool(st.get('自动弹一次', True)))


def _push():
    """把当前设置写进共享内存 —— Service 在注入前、注入后各调一次。

    这个插件没有要钩的方法，所以 ``hooks`` 是空表；``push()`` 仍然要做，
    因为它同时负责把「本插件启用了哪些东西」告诉 DLL。
    """
    host = service.host()
    host.configure(hooks=[], texts=[])
    return host.push(True) not in ('共享内存不可用',)


def _say(text=None):
    """让游戏弹一句。"""
    text = text or _settings()[0]
    result = service.host().popup(text)
    _log(f'弹窗「{text}」→ {result}')
    return result


def _auto_once():
    """等宿主挂上之后自动弹一次，然后线程退出。

    为什么要等：插件载入时游戏可能还没起来。``service.status()`` 里的
    ``hooked`` 变成 True，就说明 DLL 已经在游戏进程里跑起来了。
    """
    for _ in range(1200):  # 最多等两分钟
        try:
            st = service.status()
        except Exception:  # noqa: BLE001
            st = {}
        if st.get('hooked'):
            time.sleep(1.0)  # 给游戏主循环一点时间，别卡在加载画面里
            _say()
            return
        time.sleep(0.1)
    _log('等了 2 分钟没等到宿主挂上，放弃自动弹窗')


service = _W.plugin.Service(
    addon_name=ADDON_NAME,
    name=ADDON_NAME,
    sync=_push,
    auto=lambda: True,          # True = 插件启用着的时候，游戏一起来就自动注入
    menu=(
        ('弹一句', lambda: _say()),
        ('注入并弹一句', lambda: (service.inject_now(wait=True), _say())),
    ),
)
service.start()

if _settings()[1]:
    threading.Thread(target=_auto_once, daemon=True).start()


def on_unload():
    """卸载时收尾：Service 会停掉自己的线程、断开映射。"""
    return service.stop()

    配套的清单：

    {
    "name": "弹一句",
    "desc": "让游戏弹出一个原版系统弹窗。演示插件如何等游戏启动、注入宿主 DLL、然后调用游戏自己的能力。",
    "requires": [
        "WarpHook"
    ],
    "settings": {
        "enable": true,
        "弹窗内容": "来自插件的问候",
        "自动弹一次": true
    },
    "version": "0.1.0"
}

    三个关键点¶

    1. Service 要在顶层就创建并 start()¶

    service = _W.plugin.Service(
    addon_name=ADDON_NAME, name=ADDON_NAME,
    sync=_push, auto=lambda: True,
    menu=(('弹一句', lambda: _say()),),
)
service.start()

    sync 传的是函数本身，不是调用结果——Service 会在注入前后各调它一次。 auto 是「要不要自动注入」的判断函数，返回 True 就自动做。

    2. sync 里必须调 push()¶

    def _push():
    host = service.host()
    host.configure(hooks=[], texts=[])   # 这个插件没有钩子，交空表
    return host.push(True) not in ('共享内存不可用',)

    configure() 只是改内存里的草稿，push() 才真正写进共享内存并通知 DLL。 这两步分开是为了让插件能一次改好几样东西再一起提交。

    返回值的判断别省：万一共享内存没建起来（比如游戏还没注入），push() 会返回 '共享内存不可用' 这样的字符串而不是成功。

    3. popup() 是一次往返，不是发完就走¶

    result = service.host().popup('你好')

    它会等游戏那边回一句「已执行」或错误原因，默认最多等 2 秒（timeout=2.0）。 所以别在钩子回调里同步调它——弹窗会占住游戏主线程一会儿，弹窗没关之前 游戏是停着的。要连弹好几个，见第 07 篇的线程那一节。

    等等，那个 hooked 是什么¶

    service.status() 返回一个字典，常用的几项：

    键 含义
    ready 共享内存映射成功了吗
    hooked DLL 已经在游戏进程里跑起来了吗（最常看的）
    status_text 一行中文状态，直接打日志用
    hook_installed / hook_total 要挂的钩子挂上了几个 / 一共几个
    evt_count 你登记的钩子命中了多少次
    standalone True = 启动器已退出，DLL 还在游戏里独立跑
    log_tail 宿主 DLL 最后一行日志，出错时先看这个

    判断「能不能下命令」就看 hooked。本文的示例里用了个后台线程一直轮询它。

    一个必须知道的大坑¶

    别钩 GlobalGameManager.FixedUpdate 和 Update

    宿主自己要用 GlobalGameManager 的 FixedUpdate 当「每帧干活的入口」， 靠它来执行你的弹窗、读内存这类命令。如果你抢先把这两个方法钩了， 宿主就找不到落脚点，日志里会出现：

    pump: no free entry point, cmd channel off

    结果是 popup、read、call 这些全部失效（而且不会报错，只是没反应）。

    要每帧做点什么，用钩子钩别的方法；要拿场景根对象，直接读对象槽 29：

    scene = service.host().object_ptr(29)   # GlobalGameManager 的指针

    装上去试¶

    1. 把 弹一句/ 放进 addons/；
    2. 重启启动器，进游戏；
    3. 标题画面出来后约 1 秒，游戏里弹出一句「来自插件的问候」；
    4. 日志里能看到：
    [弹一句] 等待游戏启动…
[弹一句] 已注入（PID 12345）
[弹一句] 游戏中，命中 0 次 / 已生效 0 次
[弹一句] 弹窗「来自插件的问候」→ 已执行

    没弹出来？按顺序查：

    1. service.status()['hooked'] 是不是 False —— 是的话看 log_tail；
    2. 日志里有没有 pump: no free entry point —— 你（或别的插件）钩了 FixedUpdate；
    3. 游戏是不是在加载画面里 —— 弹出去了但被加载画面盖住，等进标题再点菜单试；
    4. addons/WarpHook/warp_host.log 里有没有 popup: empty text —— 那说明弹的是空字符串。

    到这一步你该知道的¶

    • 插件 → 共享内存 → DLL → 游戏，这条链路是所有功能的基础
    • Service = 等游戏 + 注入 + 心跳 + 托盘菜单
    • sync 里 configure 改草稿、push 提交
    • hooked 是「能不能下命令」的判据
    • 别碰 GlobalGameManager 的 FixedUpdate / Update

    下一篇开始钩游戏的方法——那才是真正能「在游戏做某件事的时候插一脚」的能力。
